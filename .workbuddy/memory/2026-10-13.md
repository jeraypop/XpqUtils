## 模式弹窗新增「开启随选朗读」开关（XpqAcc.showEngineModeDialog）
- 需求（用户原话）：新增一个开关控制是否开启「随选朗读」这个系统无障碍；
  **若调用方手动传入了 `XpqAcc.SELECTTOSPEAK`，则该开关隐藏且不发挥任何作用；没传则显示。
  为 true 时效果等价于手动传进来了 `SELECTTOSPEAK`，为 false 等价于没传。**
- 落地方案：引入「本次实际独占开启的服务」这一个概念，所有分支都读它，避免三处各判一次：
  ```kotlin
  var selectToSpeakOn = if (enableServiceString != null) true
      else MMKVUtil.get(MMKVConst.KEY_SELECTTOSPEAK_ENABLE, false)
  fun curExclusiveService(): String? =
      enableServiceString ?: if (selectToSpeakOn) SELECTTOSPEAK else null
  fun closeOtherAccTip(): String =            // 原来是 val，现改为按需计算（开关一拨就要变）
      if (curExclusiveService() != null) "2.关闭其它所有的无障碍服务…https://settings随选朗读\n\n" else ""
  ```
  - `describeMode` 里的两处 `closeOtherAccTip +` → `closeOtherAccTip() +`。
  - 确定时 `val effectiveEnableServiceString = curExclusiveService()`，两处 `applyEngineMode(enableServiceString = ...)`
    都传它（`applyModeAndGuideToSetting` 与「代码直开」路径各一处）。
  - MMKV：新增 `MMKVConst.KEY_SELECTTOSPEAK_ENABLE`（默认 false）。隐藏时不回写（与宿主开关同规则）；
    「随选朗读」开着 → 宿主无障碍行隐藏、也不回写 `KEY_UIA_ENABLE_HOST_ACC`。
- **状态变量必须声明在 `describeMode` 之前**：Kotlin 局部函数/局部变量都不能前向引用，
  而 `describeMode` 要读 `selectToSpeakOn` → `var selectToSpeakOn` 提到 `closeOtherAccTip`/`describeMode` 之前定义。
  同理开关的 `setOnCheckedChangeListener` **放在 `updateSwitchRowVisibility` 声明之后**才挂
  （而且要在 `isChecked` 初值设好之后再挂，否则初始化时白触发一次回调）。
- UI：两个开关行合并进一个竖直 `LinearLayout switchPanel`，`.setView(switchPanel)`（`setView` 只能挂一个 View）。
  新行文案：题「开启随选朗读」/副「开启后，切换到 Shizuku 模式时会一并开启系统的「随选朗读」无障碍服务」，
  颜色显式锁 `0xFF212121` / `0xFF757575`（沿用既有的防暗黑模式约定）。
- 显隐规则（合并进 `updateSwitchRowVisibility(index)`，替代原 `updateHostAccVisibility`）：
   - 随选朗读行：`index != 0 && enableServiceString == null`（**无障碍模式下隐藏**——与宿主开关同约定，`applyEngineMode`
     的无障碍分支根本不消费 enableServiceString；用户没明说，这条是我按既有约定定的，已在回复里标注）。
   - 宿主无障碍行：`index != 0 && curExclusiveService() == null`（走独占路径时隐藏，两者互斥）。
   - 开关拨动 → 重渲染标题（提示段跟着出现/消失）+ 刷新两行显隐。
- 开关初值在 `apply { isChecked = ... }` 里设，`updateSwitchRowVisibility` 由 `setOnShowListener` 与列表点击各调一次。
- `var selected = current` 从原位置（开关行之后）**上移到 `renderMode(current)` 之后**，否则开关监听读不到。
- `./gradlew :accessibility:compileDebugKotlin --offline --no-daemon` → BUILD SUCCESSFUL in 32s（无新增 warning）。

  「本次要开启的无障碍服务由调用方指定，此处仅作展示，不可修改」。未传入时行为不变（可自由切换 + MMKV 记忆）。

  简化为 `shizukuMode`（无障碍模式仍隐藏）。`hostAccRow` 判据不变（`curExclusiveService() == null`）。
- 连带：确定时的 MMKV 回写规则不变（`enableServiceString == null` 才写），只更新了注释措辞。
- 注意：传了**非** SELECTTOSPEAK 的服务时也一样只读、显示为未勾选 —— 因为 `curExclusiveService()`
  里 `enableServiceString` 永远优先，用户改开关也无效，锁死才不会有"点了没反应"的错觉。

## showEngineModeDialog 新增失败回调 `onUIAFail`（用户要求）
- 参数加在**签名末尾**（不动既有位置参数，避免 @JvmOverloads 生成的 Java 重载签名位移）：
  `onUIAFail: ((reason: String?) -> Unit)? = null`。
- 实现用局部 `val notifyFail: (String?) -> Unit = { runCatching { onUIAFail?.invoke(it) } }` 统一收口，
  声明位置必须在 `handleModeResult` / `applyModeAndGuideToSetting` **之前**（局部函数不能前向引用）。
- 三条失败路径全部覆盖，且**各只调一次**不重复：① `handleModeResult` 的 UIAUTOMATION 分支（940 附近）
  ② 同函数的 else 分支（无障碍模式失败）③ `applyModeAndGuideToSetting` 的 `failToast != null` 分支
  （这条不走 handleModeResult，会漏，必须单独补）。
- 成功路径不触发；`onUIASuccess` 的行为未动。顺带补齐了 KDoc 里此前**缺失**的 `@param onUIASuccess`
  与新增的 `@param onUIAFail`，并给 `@param onCancel` 补了「点外部/返回键关闭不触发」的说明。
- 与 `onUIASuccess` 对称：**两种模式**失败都会回调（不只是 Shizuku）。若将来只想在 Shizuku 失败时触发，
  把 `notifyFail` 移到 UIAUTOMATION 分支内即可。
- `./gradlew :accessibility:compileDebugKotlin --offline --no-daemon` → BUILD SUCCESSFUL in 33s。

## 模式弹窗加 setCancelable(false)
- 位置：`create()` 之后紧接 `dialog.setCancelable(false)`（AlertDialog.Builder 没有该方法，只能实例上调）。
- 目的：让「取消」语义完整——此前点外部/返回键能关掉弹窗但不触发 `onCancel`，宿主会漏一次取消通知。
- 已知残留：**中立按钮**（`R.string.sxzxpq`）点击仍会 dismiss 且不触发任何回调，是目前唯一能绕过回调的
  关闭路径（用户未要求处理）。`showCheckDialog` / `showUiAutomationFailDialog` 仍是 cancelable 的。
- `setCancelable(false)` 已覆盖「点外部关闭」（`setCanceledOnTouchOutside` 在不可取消时不生效），无需再加。
- 编译 BUILD SUCCESSFUL in 25s。
