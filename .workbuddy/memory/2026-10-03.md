
## 无障碍服务直接开启器（02:20）
- 需求：连接成功后让宿主能直接开启某个无障碍服务（绕过系统设置手动点亮）。
- 新增 AccessibilityEnableHelper.kt（ext/acc）：双路径——① Shizuku shell（uid 2000 自带 WRITE_SECURE_SETTINGS，UserService bind 后即可用，无需 UiAutomation 注册成功）settings put/get secure；② 回退宿主 WRITE_SECURE_SETTINGS（adb grant 一次）。自动选路。
- 严格两 Key 成对写：ENABLED_ACCESSIBILITY_SERVICES 名单（冒号分隔、读-改-写追加不覆盖他人）+ ACCESSIBILITY_ENABLED 总开关 1；写后双 Key 回读校验。disable 时名单清空则总开关一并置 0（与系统行为一致）。
- XpqAcc 新增门面：isShellAvailable() / execShell(cmd) / enableAccessibilityService(flat, ctx=appContext) / disableAccessibilityService(flat)。全部阻塞，勿主线程调。
- BUILD SUCCESSFUL（:accessibility:assembleDebug）。
- connectUiAutomation 加两个可选参数：postConnectShellCommand（连接成功后自动执行的 shell 命令）、enableServiceOnConnect（自动开启的无障碍服务展平名）。finishConnect ok 分支在后台线程串行执行（灵动岛/桥接 → shell 命令 → 开服务 → main.post onResult），runCatching 包裹，失败不影响连接成功回调。同文件三处编辑（import/签名/ok分支）严格串行提交。BUILD SUCCESSFUL。
- enableAccessibilityService 加 exclusive 参数：false=纯增量（读名单冒号追加，不影响已开启服务）；true=独占（整体替换名单只留传入服务，其它全关）。双路径（shell/WRITE_SECURE_SETTINGS）都支持；独占模式跳过"已在名单"快速通道直接覆写。XpqAcc 门面与 connectUiAutomation 同步加 enableServiceOnConnectExclusive 参数（默认 false）。用户已把 enableServiceOnConnect 默认值改为 talkback 的 SelectToSpeakService 组件名（用户手改，保留）。BUILD SUCCESSFUL。
- postConnectShellCommand 加默认值："pm grant <宿主包名> android.permission.WRITE_SECURE_SETTINGS"（默认参数在调用时求值，appContext.packageName；shell 身份执行 pm grant 合法）。连接成功即顺手为宿主申请 WRITE_SECURE_SETTINGS，之后 Shizuku 不在也能走路径②开服务；传 null 可显式关闭。
- BUILD SUCCESSFUL。
