## 纠正：`FEEDBACK_ALL_MASK` 并非「基本等于不过滤、feedbackType=0 会被滤掉」（同日）
- 起因：用户追问「能包含所有的类型吗」。SDK sources 里**没有** `com/android/server`，只能在线取
  AOSP 服务端源码，回查后发现上一轮写进 `AccIsOpenUtil.getEnabledServiceIds` KDoc 的那句**是错的**。
- 事实：`AccessibilityManagerService.getEnabledAccessibilityServiceList(feedbackType, userId)` 的判定是
  `if ((service.mFeedbackType & feedbackType) != 0 || feedbackType == AccessibilityServiceInfo.FEEDBACK_ALL_MASK)`，
  第二条是**显式通配分支** → `feedbackType = 0` 的服务**照样返回**。
  该分支 **Android 14 才加入**（逐版本核实：8.1 / 9 / 10 / 11 / 12 / 13.0.0_r1 都只有位与测试，
  `android-14.0.0_r1` 与 `main` 有）。`FEEDBACK_ALL_MASK = 0xFFFFFFFF`（`AccessibilityServiceInfo.java:205`）；
  `feedbackType = 0` 的来源 = `android:accessibilityFeedbackType` 属性**缺省值就是 0**
  （`AccessibilityServiceInfo.java:746-748`）。
- 顺带核实到两道**此前未记录**、会静默清空 AM 列表的闸：
  ① `mUiAutomationManager.suppressingAccessibilityServicesLocked()` 为 true 时本方法**直接
     `return Collections.emptyList()`**（源码注释原文 "The automation service can suppress other
     services."）—— 与「真的一个服务都没启用」无法区分。该函数 =
     `(mUiAutomationService != null || !useAccessibility())
      && ((mUiAutomationFlags & FLAG_DONT_SUPPRESS_ACCESSIBILITY_SERVICES) == 0)`。
     **本库不受影响**：`InvisibleAutomation` 走 `connect(int)` 分支并传 `flagDontSuppress`(0x1)；
     只有老版本回退到无参 `connect()`（flags = 0）时才会踩到。
  ② `AccessibilityManager.getServiceLocked()` 为 null 时也是 `Collections.emptyList()`（已知，878 行）。
- 改动：只改 `AccIsOpenUtil.getEnabledServiceIds` 的 KDoc（把那句错的换成带出处的正确结论 + 两道闸说明）。
- 手法备忘：AOSP 服务端源码用
  `raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/<branch>/services/accessibility/java/
  com/android/server/accessibility/*.java` 取（`android.googlesource.com` 的 WebFetch 会 fetch failed；
  本机 curl 也不可用）。分支名有 `android-<ver>.0.0_r1`、`android14-release`、`main`，
  **逐版本比对可定位某个分支是哪一代引入的** —— 这比"我记得"可靠得多。

## `AccIsOpenUtil` 两个函数返回值形态统一（同日，用户要求）
- 问题：`getEnabledServiceIds`（AMS）给的是**短式** `pkg/.Cls`，`getEnabledServiceIdsFromSecure`
  给的是**长式** `pkg/pkg.Cls` → 两个"看起来同类"的函数结果**不能直接比较**（上一轮只在 KDoc 里写了警告）。
- 改法：新增私有扩展 `String.toCanonicalComponent()`：
  `ComponentName.unflattenFromString(this)?.flattenToString() ?: this`，**统一成长式**
  （长式 = `Settings.Secure` 名单与写回 API 用的形态，也是 `XpqAcc.enableAccessibilityServiceOnly`
  做 `contains` 校验时用的形态）。
  两个函数各自 `.map { it.toCanonicalComponent() }`。
- 选择长式而非短式的原因：短式是 `flattenToShortString()` 的展示优化（类名与包名同前缀时压掉），
  信息有损；长式可直接写回系统。解析失败（不含 `/`、或 `/` 后为空，如遗留脏数据）**原样返回**，
  不丢项 —— 保持"读到什么就是什么"。
- 影响面：`isAnyInWhiteList` 用的是 `id.contains(白名单类名)`，长式仍含类名 → 判定行为不变。
  库内无其它调用点（只有 `isAccessibilityEnabled` 用它俩）。
- 顺带：`XpqAcc.enabledAccessibilityServices()`（走 helper，读 secure 名单）本来就是长式，
  现在与 AM 侧一致，**可以直接互比**。
- 验证：`./gradlew :accessibility:compileDebugKotlin :app:compileDebugKotlin --offline --no-daemon`
  → **BUILD SUCCESSFUL in 26s**。
