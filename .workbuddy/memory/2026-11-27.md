## 调研：宿主传 http(s) 网页地址是否受支持（未改动库代码）
- **通路本身支持**：`privacy_GuoNei_SJ(activity, privacy, terms)` → `XpqPrivacyDialog` 构造把非空值写进
  companion `var xpqprivacypolicy/xpqterms` → `XPQTermsActivity`/`XPQPrivacyPolicyActivity` 里
  `webView.loadUrl(...)`。`loadUrl` 对 `file://`/`http(s)://` 通吃，**库已声明 INTERNET 权限**，
  manifest 里 `application usesCleartextTraffic="true"`（http 也不拦）。实机（TB320FC / Android 15）
  用 `https://example.com` 验证 → `onPageFinished: title=Example Domain`，渲染正常。
- 用户给的 `https://quzhuligpt.gitlab.io/mqd_privacy_policy` **本身是坏的**：302 到
  `https://gitlab.com/users/sign_in`，再被 Cloudflare 挡成 403 `title=Just a moment...`
  （GitLab Pages 站点未部署 / 项目私有 / 路径不存在时都这样）。本机 curl 结果一致。
- **协议页 WebView 现状（两个 Activity 都是这个配置，全是隐患）**：
  1. **一行 `settings` 都没设** ⇒ `javaScriptEnabled` 默认 **false**。纯静态 HTML 能看；
     Cloudflare 挑战页 / VitePress / Docsify / 任何 JS 渲染站 ⇒ 永远白屏或停在「Just a moment...」。
  2. `shouldOverrideUrlLoading` **恒 return true**（两个分支都 true，只有上层判断差异，无意义）⇒
     **页内链接点击全部被吞**（条款里的《个人信息收集清单》跳不动、锚点跳不动、cookie 提示点不动）。
     注意：初始 `loadUrl` 不走这个回调，服务端 302 也不走 ⇒ 首次加载仍能成功，问题只在用户点链接。
  3. `webViewClient` 无 `onReceivedError` ⇒ 断网/DNS 失败/403 **零提示**，用户只看到白屏或别人家的登录页。
  4. 布局 = 40dp 写死中文标题（「用户协议」/「隐私政策」）+ FrameLayout：**没有返回按钮**（只能系统返回键）、
     **没有 loading 指示**；英文宿主标题仍是中文。
  5. `WebView(applicationContext)`（官方不建议，但实测这台机器能正常加载，可暂不动）。
- `xpqprivacypolicy/xpqterms` 是 companion 静态 `var` = 进程级全局；且 `XpqPrivacyDialog.init` 里
  `if (!TextUtils.isEmpty(privacy))` ⇒ **传空串保留上一次的值**，不回退 asset 默认页。
- 合规提醒：录屏/审计要求「同意前不得联网」—— 只在用户**主动点链接**后才 `loadUrl` 是允许的，
  千万不要在弹窗出现时就预加载；另外国内审核要求条款**离线可见**，远程页需配 asset 兜底。

## 协议展示页重构：支持 http(s) 网页（已完成 + 实拍）
- 新增基类 `privacypolicy/BasePrivacyWebActivity`（abstract，3 个抽象属性：
  `pageTitleRes` / `pageUrl` / `fallbackAssetFileName`），`XPQTermsActivity` 与
  `XPQPrivacyPolicyActivity` 各降到 ~20 行、只声明这三样。展示逻辑全在基类。
- 布局合并为 **`activity_xpq_privacy_web.xml`**，**删掉** `activity_xpqterms.xml` /
  `activity_xpqprivacy_policy.xml`（这两个只有标题写死文字不同，grep 确认无外部引用）。
  结构：48dp 标题栏（44dp 返回 + 居中标题 + 44dp 右侧占位保证真居中）→ FrameLayout 装 WebView
  → 居中 ProgressBar → 失败态 LinearLayout（提示 + 重试）。
- 修掉四处：① `javaScriptEnabled = true` + `domStorageEnabled`（原来一行 settings 都没设，
  默认关 JS，VitePress/Cloudflare 挑战页必白屏）；② `shouldOverrideUrlLoading` 改成
  **http/https/file/about/data 返回 false 交给 WebView**，其余 scheme 走 `Intent.ACTION_VIEW`——
  旧版两个分支都 `return true` 把页内链接全吞了；③ 加 `onReceivedError`（
  **只认 `request.isForMainFrame`**，否则图片挂掉也弹错误页）；④ 标题栏加返回箭头、标题走
  `xpqprivacy_title_terms/privacy`（四个 values 都补），不再写死中文。
- **失败兜底链**：远程失败 → `assetExists(fallback)` 用 `assets.open(name).close()` 判存在 →
  切 `ANDROID_ASSET + fallback`；`currentUrl` 已是 asset 时**不再兜底**（防死循环）；都没才显示错误页。
  另外 `normalizeUrl()` 把裸文件名（`xpqlib_privacy.html`）当 asset、带 `://` 原样用。
- 新增 strings（4 个 values 目录）：`xpqprivacy_title_terms` / `xpqprivacy_title_privacy` /
  `xpqprivacy_web_error` / `xpqprivacy_web_retry`。zh-rTW 用「使用者條款 / 隱私權政策」，zh-rHK 用「用戶協議 / 私隱政策」。
- **实拍（TB320FC / Android 15）四态全过**：
  ① `https://example.com` → 标题「用户协议」+ 返回箭头 + 网页正常渲染；
  ② 点页内 "Learn more" → **成功跳 iana.org**（旧版会被吞）；
  ③ 不存在的域名 → **自动降级到宿主 assets 里的 `xpqlib_terms.html`**（真实条款页，离线可见）；
  ④ 兜底 asset 也不存在 → 错误页「页面加载失败，请检查网络后重试」+ 蓝色「重试」，点重试不崩、点返回回桌面。
